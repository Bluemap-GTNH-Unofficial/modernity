# modernity

Optional [Modernity-GTNH](https://github.com/ModernityGTNH/Modernity-GTNH) look for BlueMap GTNH maps (plan.md §11,
D6). From a user-supplied Modernity release it builds two BlueMap resource packs:

| Pack | Built by | Content |
|---|---|---|
| `modernity-2.9.x-<sha>-modded-2.9.0-RC-2.zip` | `modernity modded` | a complete GTNH client export (`tools/gtnh-exporter`) made with Modernity and MyCTMLib loaded: models, blockstates and textures of all modded blocks, plus the 1.7 vanilla icons modded blocks use (`gtnh_minecraft_1_7`) |
| `modernity-2.9.x-<sha>-vanilla-1.13.zip` | `modernity vanilla` | Modernity's vanilla block textures, renamed from the 1.7.10 layout (`assets/minecraft/textures/blocks/<old>.png`) to the 1.13 layout BlueMap renders vanilla blocks with (`textures/block/<new>.png`) |

**Licence.** Modernity-GTNH is CC BY-NC-SA 4.0. Its files are never committed here, and the tool only takes a
release the user downloaded. Both generated packs contain Modernity-derived textures, so they carry a
`LICENSE-NOTICE.txt`, and the vanilla pack also carries Modernity's README with its credits. Do not redistribute them
commercially, and share them under the same licence. The rename table in `data/` holds only texture names. Part of it
comes from ResourcePackConverter (MIT, see below).

Python ≥ 3.12 with uv; the only dependency is Pillow. Paths are relative to the workspace `WS`, the directory that
contains `BlueMap-GTNH/`; override it with `BMGTNH_WORKSPACE`.

## Reproduce

```bash
cd BlueMap-GTNH/tools/modernity
uv sync --group dev
uv run modernity fetch          # newest weekly-2.9.x-* release -> WS/downloads/modernity/
uv run modernity vanilla        # -> WS/out/modernity/modernity-2.9.x-<sha>-vanilla-1.13.zip + vanilla-report.json
uv run modernity modded --baseline \
  --mod-jar ../gtnh-exporter/build/libs/bluemap-gtnh-exporter-0.1.0.jar \
  --extra-states-dump ../../../out/scenes/gtnh-zoo/dump.ndjson   # -> modernity-2.9.x-<sha>-modded-2.9.0-RC-2.zip
uv run modernity compare        # -> WS/out/modernity/modded-report.json (counts below)
uv run modernity e2e vanilla-zoo gtnh-zoo   # -> WS/out/e2e-modernity/{default,modernity,compare}/
uv run --group dev pytest
```

### Commands

- **`fetch [--tag TAG]`** picks the newest `weekly-2.9.x-*` release of `ModernityGTNH/Modernity-GTNH` (the `2.9.X`
  branch's weekly build) through the GitHub API, or the release named by `--tag`. It downloads
  `Modernity-2.9.x-*.zip` and `MyCTMLib-*-29x.jar` and checks each against the sha256 digest GitHub reports. It writes
  `release.json` (tag, files, digests), which later commands read. If `GITHUB_TOKEN`/`GH_TOKEN` is set, it is used.
  Every other command also accepts `--pack ZIP`; with it, a `MyCTMLib-*-29x.jar` next to the zip is used.
- **`vanilla`** converts the pack's vanilla block textures (see below).
- **`modded [--baseline] [--no-myctmlib] [--client-dir DIR] [--mod-jar JAR] [--extra-states-dump DUMP ...]`** runs
  `gtnh-client export` (tools/gtnh-exporter/launcher) with the following options:
  - `--resource-pack <Modernity zip>`
  - `--extra-mod <MyCTMLib jar>`
  - `--pack-suffix modernity`
  - `--out WS/out/modernity/export-modernity`

  The launcher installs the pack and the mod only for that run, then restores `mods/` and `options.txt`. The tool then
  copies the result to `modernity-<release>-modded-<pack version>.zip` and adds `LICENSE-NOTICE.txt`. With
  `--baseline`, it first runs the same export (same jar, client and extra states) without Modernity into
  `export-default/`, which `compare` and `e2e` use as the default pack.
- **`compare [--default PACK] [--modded PACK]`** compares the default export with the Modernity export texture by
  texture (`modded-report.json`).
- **`e2e SCENE... [--default PACK] [--build] [--compare-only]`** runs `testing/e2e` twice:
  1. `uv run e2e run SCENE... --no-build --packs <default> --packs <modded> --packs <vanilla>`;
  2. the same with only the default pack.

  It copies each run's `shots/`, `report.json`, `bluemap.log` and `packs.txt` (the `config/packs` listing in BlueMap
  priority order) to `WS/out/e2e-modernity/{modernity,default}/<scene>/`. It then writes
  `compare/<scene>/<view>.png` (default | Modernity | pixels differing by more than 24, in red) and
  `compare/compare.json`. Expect e2e to exit 1 on the Modernity run, because its views differ from the default
  baselines.
- **`table [--check]`** regenerates `data/renames-1.7.10-to-1.13.json` from the Mojang client jars. The jars are
  downloaded SHA-1 verified into `WS/downloads/mc/`. `--check` only verifies that the committed table is current.

## Vanilla textures: 1.7.10 -> 1.13

The rename table `data/renames-1.7.10-to-1.13.json` is generated by `renames.py` from three sources (later ones win):

1. the identity, when the 1.7.10 name also exists in the 1.13 client jar (111 names);
2. ResourcePackConverter's `forwards/blocks.json` `1_13` mapping (212 names). This is agentdid127/ResourcePackConverter
   at pinned commit `63ba2cd`, MIT, Copyright (c) 2024 agentdid127, downloaded sha256-verified;
3. `MANUAL` in `renames.py` (12 names): names ResourcePackConverter lacks or maps to a texture that does not exist
   (`trip_wire_source -> trip_wire_hook`), plus textures that 1.13 split or merged.

Generation fails if any target is missing from the 1.13 jar, if any 1.7.10 block texture is neither mapped nor listed
in `UNMAPPED` with a reason, or if two sources map to the same target. Result: all 349 1.7.10 block textures are
accounted for. 335 are mapped to 339 targets and 14 are unmapped.

Split and merged textures:

| 1.7.10 | 1.13 | Operation |
|---|---|---|
| `command_block` | `command_block_{front,back,side,conditional}` | copy to all four (1.7.10 uses one texture for all faces) |
| `redstone_dust_cross` | `redstone_dust_dot` | keep only the pixels inside the bounding box of the vanilla 1.13 dot (5,5)-(11,11), scaled to the pack resolution |
| `redstone_dust_line` (horizontal) | `redstone_dust_line0`, `redstone_dust_line1` (vertical) | rotate each animation frame clockwise (the orientation that best overlaps the vanilla line0 mask) |
| `redstone_dust_cross_overlay` | `redstone_dust_overlay` | copy (1.13 has a single overlay) |
| `water_still`, `water_flow` | same names | divide RGB by the default water tint `#3F76E4` (clamped). 1.7.10 water textures are coloured and drawn untinted; 1.13 water textures are grey and multiplied by the biome water colour. Modded biomes get `#3F76E4 × waterColorMultiplier` from `gtnh-runtime`, and most vanilla biomes get `#3F76E4` from the 1.19.4 datapack, so in default-coloured biomes the result looks the way Modernity designed it. Modernity's `water_still` comes out at mean grey 177, the same as vanilla 1.13's 177 |
| `double_plant_*`, `log_*_top`, `grass_side_overlay`, … | `sunflower_front`, `oak_log_top`, `grass_block_side_overlay`, … | plain renames from ResourcePackConverter. The 1.13 models use the same top/bottom and base/overlay split as 1.7.10 |

Unmapped (`UNMAPPED`, with reasons in the table):

- `bed_{feet,head}_{end,side,top}`: 1.13 beds are drawn from the entity texture `textures/entity/bed/<colour>.png`, which
  has a 64×64 model UV layout. There is no block texture to replace.
- `leaves_*_opaque` (6): the fast-graphics variants. 1.13 only has the cutout leaves texture.
- `flower_paeonia`: the single-block peony. 1.13 only has the double plant, `peony_top/bottom`.
- `redstone_dust_line_overlay`: 1.13 has a single overlay, which is taken from the cross overlay.

The converter copies Modernity's `.png.mcmeta` `animation` section (other sections such as `myctmlib` are dropped);
PNGs are byte-identical copies unless an operation applies. Modernity also ships 500 modern-named textures in
`textures/blocks/` for blocks backported to 1.7. The 136 of them whose name is a 1.13 block texture are copied
unchanged, unless a 1.7.10 mapping already writes that target (none do). The 364 post-1.13 names, such as
`amethyst_block` and `bamboo_*`, are listed in `vanilla-report.json`. Modernity's MCPatcher CTM for vanilla glass,
bookshelves and sandstone (53 `.properties`) is not converted: BlueMap uses the base textures.

## Modded textures

- **Modernity icon names.** Modernity keeps the mods' icon names. When the client exporter reads every sprite through
  the resource manager with the pack enabled, the overridden textures come out automatically.
- **Normalised paths.** The pack's textures use the normalised paths of the default pack, so `compare` maps each
  exported texture back to its 1.7 resource with the inverse of normalisation N (`keys.py`, checked against
  `testing/fixtures/resource-key-vectors.json`).
- **Why MyCTMLib is loaded.**
  - The release notes say "CTMLIB IS REQUIRED FOR CONNECTED TEXTURES".
  - The pack's `pack.mcmeta` turns on MyCTMLib JSON models for AE2 and bees.
  - Without MyCTMLib the pack still loads: the client log shows no missing-texture errors, and the export differs from
    the MyCTMLib export in only 74 + 13 one-sided files and 152 changed models/blockstates (measured with the exporter
    before its CTM fallback fix).
  - Without MyCTMLib, however, AE2 blocks keep their old models.
  - Before the exporter learned to fall back to base icons, MyCTMLib also mattered for CTM capture. Angelica's
    MCPatcher CTM, driven by GT's own `mcpatcher/ctm` data rather than Modernity's, captured some GregTech blocks as CTM
    tile `0.png`: 93 textures in the default export and 31 with Modernity + MyCTMLib. The current exporter writes no
    `mcpatcher/ctm` tiles to either pack.
  - `--no-myctmlib` drops the jar.
- **CTM.** MyCTMLib connected textures are a `myctmlib` section in a texture's `.mcmeta` that points at a connection
  sheet (`<name>_ctm`). The exporter writes the texture's own PNG, which is the base tile; no connected textures are
  rendered yet.

**Vanilla** (`vanilla-report.json`, built in 0.2 s):

- **Modernity block textures:** 849 in `assets/minecraft/textures/blocks/`. All 349 1.7.10 names are present.
- **Mapped:** 335 of the 1.7.10 textures map to 339 1.13 textures. Unmapped: 14.
- **Modern names:** 136 copied unchanged; 364 have no 1.13 counterpart.
- **Written:** 475 1.13 textures in total. 150 of them are pixel-identical to vanilla 1.13: Modernity reuses
  modern textures, e.g. grass, stone and dirt. 325 change the look.
- **Animations:** 14.

**Modded** (`modded-report.json`; each export takes about 48 s of client run):

- **Shared textures overridden:** 5221 of the 13800 textures present in both exports differ. By namespace: gregtech
  1762, `gtnh_minecraft_1_7` 327, miscutils 266, botania 265, tinker 238, and so on, across 80 namespaces.
- **Textures only in the Modernity export:** 1272.
  - gregtech: 1254, overlay icons that Modernity adds and GT's own jar lacks;
  - ic2: 13;
  - myctmlib: 5.
- **Textures only in the default export:** 16 (ic2 8, appliedenergistics2 5, gregtech 2, projectred 1), replaced by
  MyCTMLib models or Modernity variants.
- **Exported textures whose 1.7 resource Modernity ships:** 5371. 5319 of them are pixel-identical to Modernity's PNG.
- **Changed without a matching Modernity PNG:** 196. These are IC2 sheet slices, Extra Utilities composites and
  Railcraft.
- **CTM:**
  - Modernity has 535 MyCTMLib textures, all with the default `compact` method.
  - 344 of them are used by exported blocks with the base tile.
  - 342 of those are verified pixel-identical to Modernity's base PNG. The other 2 are GoodGenerator
    `antimatterContainmentCasing` and `fieldRestrictingGlass`.
  - The 10 `ctm` mcmeta sections, from Twilight Forest tower devices, are emissive metadata, not connections.

**Screenshots** (`WS/out/e2e-modernity/compare/<scene>/<view>.png`, default vs Modernity):

| vanilla-zoo | top-flat | 2.3 % | 17.3 % |
| vanilla-zoo | perspective | 0.4 % | 6.1 % |

The differences are smaller than expected, for two reasons. Modernity is mostly modern vanilla art, and 150 of its
vanilla textures already equal what BlueMap renders. At these camera distances, most texture changes stay below the
e2e tolerance of 24. Missing-texture (magenta) shares are practically unchanged: 0-0.49 % of the view by default,
0-0.44 % with Modernity (`report.json`).

## Enabling it on a server

1. Generate both packs as described above, against the same exporter version as the server's default pack.
2. Copy both zips into `config/bluemap/packs/`, next to the default `bluemap-gtnh-resources-2.9.0-RC-2.zip` and the
   addons.
3. Run `/bluemap reload`, then `/bluemap force-update` (or the CLI with `-f`/`--force-render`) to re-render the
   tiles with the new textures.

**Pack order.** `BlueMapService.getPackRoots` loads `packs/*` in **reverse file-name order**, and the first pack that
provides a resource wins (atlases are merged); see research/bluemap-codebase-map.md §3. The generated names start with
`modernity-`, which sorts after `bluemap-gtnh-resources-…` and `gtnh-runtime`, so they take priority. Do not rename them
to anything that sorts before the default pack, such as the exporter's own `bluemap-gtnh-resources-2.9.0-RC-2-modernity.zip`:
`-` sorts before `.`, so the default pack would win. The modded pack is a complete export, so the default pack may also
be removed. The vanilla pack only replaces textures; BlueMap still takes models and blockstates from the 1.13 client jar
and the `legacy` addon.

To turn it off, delete the two zips, then reload and force-update.
